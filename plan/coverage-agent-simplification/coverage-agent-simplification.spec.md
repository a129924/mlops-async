# coverage-agent-simplification Specification

## Acceptance Criteria

1. The correction topic exists at `analysis/coverage-agent-simplification/` and
   `plan/coverage-agent-simplification/`.
2. `pyproject.toml` uses `[tool.coverage.report].fail_under = 90`.
3. `.pre-commit-config.yaml` `coverage-check` uses `--cov-fail-under=90` and a 90% hook name.
4. `README.md` does not claim `scripts/coverage_agent.py` generates test stubs.
5. `scripts/coverage_agent.py` and `tests/unit/test_coverage_agent.py` are removed.
6. Parent `coverage-agent` analysis and plan artifacts state that stub-generation behavior is superseded by this correction topic.
7. `.coverage-reports/coverage.json` is generated by pytest-cov and contains file-level and function-level missing-line evidence.
8. `VERSION`, `uv.lock`, and git tags are unchanged by this topic.

## Behavioral Scenarios

### Scenario 1: Coverage gate uses repo policy

- **Given**: repository governance expects 90% coverage.
- **When**: the correction is complete.
- **Then**: `pyproject.toml` and `.pre-commit-config.yaml` both enforce 90%.

### Scenario 2: Agent uses pytest-cov JSON evidence

- **Given**: `uv run pytest tests/unit/ --cov=src/mlops_async --cov-report=json:.coverage-reports/coverage.json --cov-report=term-missing` has run.
- **When**: an Agent needs to inspect coverage gaps.
- **Then**: it reads `.coverage-reports/coverage.json` fields such as `files[*].missing_lines` and `files[*].functions[*].missing_lines` instead of running a custom AST mapper.

### Scenario 3: No automatic test stub generation

- **Given**: coverage JSON shows a function has missing lines.
- **When**: the gap is not covered by the current topic Test Plan or requires human judgment.
- **Then**: the Agent reports a human feedback item and does not write to `tests/unit/`.

### Scenario 4: Helper deletion is semantically complete

- **Given**: `scripts/coverage_agent.py` is deleted.
- **When**: current documentation and plan artifacts are searched for `coverage_agent`, `stub`, or `assert False`.
- **Then**: no current-truth artifact requires the deleted helper or describes stub generation as active behavior.

### Scenario 5: README is corrected without release mutation

- **Given**: README currently describes v0.10.4 coverage-agent behavior.
- **When**: this correction is complete.
- **Then**: README describes coverage gate plus JSON/human triage, while `VERSION`, `uv.lock`, and git tags remain unchanged.

## Error / Edge Cases

- If the managed worktree path or branch already exists, stop for human decision before editing.
- If coverage falls below 90 after deleting helper tests, stop and report which source gaps remain rather than generating stubs.
- If parent artifacts and correction artifacts conflict after backfill, treat parent artifacts as incomplete current truth and return to creator rework.
- If `.coverage-reports/coverage.json` appears in `git status --short`, remove it from staging / working tree before publish.
